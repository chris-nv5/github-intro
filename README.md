# GitHub Learning Group
A beginner-friendly repository for learning Git and GitHub together as a coworker group. Use the exercises to practice, the resources to look things up, and pull requests to learn from one another.

## Goals
- Learn Git fundamentals
- Practice branching and pull requests
- Understand GitHub collaboration workflows
- Build confidence using GitHub in a team environment

## Suggested Learning Path
1. **Git basics:** install Git, configure your identity, clone a repository, and make a commit. Start with [your first commit](exercises/first-commit.md).
2. **Branching and merging:** make changes on a separate branch and learn how branches come together.
3. **Pull requests and code review:** propose a change, review a teammate's work, and respond to feedback.
4. **Issues and project tracking:** describe work clearly and track it from idea to completion.
5. **GitHub workflow best practices:** keep changes focused, communicate early, and leave a useful history.

## Topics Covered
- Git installation and setup
- Creating repositories
- Cloning and committing
- Creating branches
- Merging and resolving conflicts
- Using pull requests
- Working with issues
- Basic team collaboration flow

## Folder Structure
- `exercises/` – hands-on practice guides
- `resources/` – [Git cheat sheet](resources/git-cheat-sheet.md) and [Git/GitHub glossary](resources/glossary.md)
- `notes/` – personal or team learning notes, including a [learning log template](notes/learning-log-template.md)
- `templates/` – reusable [issue](templates/issue-template.md) and [pull request](templates/pull-request-template.md) templates

## Beginner Plan
### Week 1
- Install Git and set up your GitHub account
- Create or clone a repository
- Complete [your first commit](exercises/first-commit.md)

### Week 2
- Create a feature branch for a small change
- Commit the change and switch between branches
- Compare your branch with `main`

### Week 3
- Open a pull request with a clear summary
- Review a teammate's change and leave constructive feedback
- Merge an approved pull request

### Week 4
- Create an issue for a small improvement
- Use issues and project boards to track work
- Practice the team's branch, review, and merge workflow

## Contributing
Each member can add notes, complete or propose exercises, improve documentation, and suggest learning topics. For a first contribution, create a branch, make one focused change, push it, and open a pull request for the group to review. Use the [issue template](templates/issue-template.md) to suggest a topic or report a problem.

When reviewing, ask questions when something is unclear, describe the impact of suggested changes, and acknowledge what is already working. The goal is to help each other learn, not just to approve code.
